## 1. What's already strong

- The data is clearly labelled as literature, assumed or simulated, and the app consistently warns that values are simulated rather than measured.
- It covers the whole workflow: inventory → hotspots → capture scenario → carbon flow → MRV-style report and PDF export.
- It has a real CAD pipeline (parametric `build123d` script → GLB → React Three Fiber viewer).
- It has unit tests for the simulation and data layers.

## 2. Critical issues a judge will spot (fix first)

### 2.1 The headline result is 0.27% capture, caused by sizing
- Feed: 150,000 Nm³/h × 22% × 1.977 kg/Nm³ ≈ **65 t CO₂/h**.
- Sorbent: 1,000 kg × 4 mmol/g × 44 g/mol ≈ **176 kg CO₂ per cycle**.
- The bed therefore saturates in **about 12 seconds** (the dashboard shows "time to regeneration 00:00:12"), then sits full for the rest of the 4-hour cycle. The result is 0.27% monthly capture while the monitoring page shows 78.4%.
- **Fix:** add a *sizing mode*. The user picks a target capture rate (for example 90%) and a cycle time, and the model calculates the sorbent mass needed: 65 t/h × 0.9 × 4 h ÷ 0.176 t CO₂ per t sorbent ≈ 1,300 t of sorbent per bed. Alternatively, frame the default as a **slipstream pilot** (for example 0.5–1% of kiln flow) and show it achieving ~90% on that slipstream. Both are honest and look far better than 0.27%.

### 2.2 No net-CO₂ figure, and the current numbers are net-positive
- Modelled energy is about **2,290 kWh per t CO₂ captured**. At the demo's own Peninsular Malaysia grid factor (0.74 kg/kWh), that is about **1.7 t CO₂ emitted for every 1 t captured**.
- The app never calculates *net CO₂ avoided = captured − energy emissions*. For a carbon-impact competition, this is the most important number missing.
- **Fix:**
  - Add a "Net CO₂ avoided" KPI with an energy-source selector: grid, solar, or **kiln waste heat**.
  - Charge gas-handling and cooling energy only for the gas actually treated (or the slipstream), not the full 150,000 Nm³/h. Most of the 291 MWh comes from processing flue gas while the bed is already saturated.
  - Regenerating at 110 °C is a strong fit for cement-kiln waste heat (preheater and cooler exhaust are typically hotter than this; verify with a source). That waste-heat story is what can turn the result net-negative.

### 2.3 The process physics is mostly scripted
- The 78.4% "capture efficiency" is a fixed parameter plus a sine-wave drift (`target-capture-efficiency` and `capture-efficiency-drift`). It is not calculated from the bed.
- There is only **one bed**, so nothing is captured during regeneration. Real temperature-swing adsorption runs 2–3 beds in rotation.
- **Fix:** add a simple **breakthrough-curve model** (a linear driving force or a logistic breakthrough fit) with 2-bed alternation. Later, fit its parameters from the real sensor rig (section 4).

### 2.4 Errors in the demo data (`viewer/src/data/demoOrganisationCarbon.json`)
| Record | Problem |
|---|---|
| Landfilled waste | Unit is `kWh` with factor `kg CO2e/kWh`. Waste should be in tonnes. |
| Cement kiln | `150000 litre × 0.52 kg CO2/litre`, classified **Scope 2**. Kiln process (calcination) emissions are Scope 1, and ~0.52 is a *t CO₂ per t clinker* figure, not per litre. |
| Road freight | Scope 1 in one record, Scope 3 in the others. |
| Sabah grid factor | `year: 2014`, but the source is the 2022–2024 grid emission factor document. |
| Source URLs | Contain `?utm_source=chatgpt.com`. Strip these; judges will notice. |

The material is named **XS-TEPA-700** in the model but **CS-TEPA-700** in the literature. This is probably a typo; align the names, or explain the difference if it is intentional.

### 2.5 Repository hygiene
- The same 709 KB GLB is committed twice (`GLB/` and `viewer/public/models/`).
- `.agents/skills/` (~1 MB, 15 vendored agent skills) adds noise for reviewers. Move it out or into `.gitignore`.
- `src/chitosan_co2_capture.py` imports `cadgen`, which has no requirements file or install note, so the CAD model can't be regenerated by others.
- There is no LICENSE file.
- CI runs `npm run build` but not `npm test`. Add `npm test` to `deploy-pages.yml`.
- 22 JSX lines are over 1,000 characters (for example in `EmissionHotspotsPage.tsx` and `CarbonFootprintCalculatorPage.tsx`). Split them into components so the code can be reviewed.
- The Process Monitoring header says "Live" while showing simulated data. Rename it "Simulated live" until real sensors are connected.

## 4. Build plan: benchtop chitosan capture rig

### Concept
A clear acrylic or glass column (~25–40 mm diameter, ~200 mm long) packed with chitosan beads, ideally amine-modified (TEPA or PEI impregnated). There is a CO₂ sensor before and after the column, plus a heater for regeneration. An ESP32 streams the readings to the dashboard, which plots a **live breakthrough curve** and calculates the **measured capacity in mmol/g**.

```
[CO₂ source] → [flow meter/needle valve] → [Sensor IN] → [Chitosan column + heater + thermocouple] → [Sensor OUT] → vent
                                                         ↑
                                                  ESP32 → Wi-Fi/MQTT or Web Serial → ChitoCapture "Live" mode
```

### Parts list (indicative)
| Part | Suggestion | Notes |
|---|---|---|
| Microcontroller | ESP32 DevKit | Wi-Fi plus Web Serial |
| CO₂ sensors ×2 | **Sensirion SCD30/SCD41** (0–10k/40k ppm) for a low-concentration demo, or **ExplorIR-M 5%/20%** or **SprintIR-WF-20** for kiln-like 5–20% | Use two matching sensors and cross-calibrate in ambient air |
| CO₂ source | Small CO₂ cylinder with a regulator (aquarium or soda type), or a baking soda + citric acid generator | Dilute with air to a stable concentration |
| Flow control | Aquarium pump + needle valve + rotameter (0.1–1 L/min), or a cheap mass flow sensor (e.g. Sensirion SFM3000) | Flow is needed for the mass balance |
| Column | Acrylic tube with 3D-printed end caps (PETG) and mesh/glass wool plugs | The repo already has CAD and Bambu skills |
| Heater | Heating tape or Nichrome wire + MOSFET + **MAX31865/PT100** or a K-type thermocouple + MAX31855 | Regenerate at ~80–110 °C with an N₂ or air purge |
| Optional | Humidity sensor (SHT45), pressure sensor (BMP390), small OLED | Flue-gas humidity matters for amine sorbents |
| Sorbent | Commercial chitosan flakes → beads (acetic acid dissolve, NaOH drop), optionally impregnated with TEPA/PEI | Good story: chitosan from **shrimp/crab-shell waste** |

### What the dashboard gains
1. A new **"Live Rig" data mode** next to "Simulated" (ESP32 → MQTT over WebSocket, or the browser's Web Serial API, with no backend needed).
2. A real-time breakthrough curve of C_out/C_in against time.
3. Measured capacity: integrate (C_in − C_out) × flow over time ÷ sorbent mass → **mmol/g**. This replaces the assumed 4 mmol/g with a *measured* value, and the provenance changes from `assumption` to `measured`.
4. Cycle stability: run 5–10 adsorption/regeneration cycles live and show capacity retention.
5. Scale-up: feed the measured capacity into the kiln model (with the sizing fix from 2.1) → "with our sorbent, a slipstream of X Nm³/h needs Y t of sorbent and captures Z t/yr, net of energy."

### Safety notes
- CO₂ at high concentrations is an asphyxiant. Ventilate the outlet and keep cylinder use small and supervised.
- TEPA/PEI are corrosive amines. Use gloves and goggles and work in a fume hood if possible.
- The heater needs a thermal cutoff, and the acrylic must stay below its softening point (~80–100 °C). Use a glass or metal column if you regenerate at 110 °C.
